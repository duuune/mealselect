# 今夜これ — 夕飯決定アプリ（Phase 0）

夕飯が決まらないのは選択肢が足りないからではなく、多すぎるから。
このアプリは**一度に1枚だけ提案する**。「タイ料理」「それ以外」の2レーンをタブで切り替え、
気に入らなければ「別のを見る」で次の1枚（回数制限なし。当初あった3回制限は撤廃した）。

検証に必要ないものは意図的に作っていない（DB・API・認証・レシピ・写真・検索・推薦モデルなし）。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `dishes.yaml` | 料理マスタ140品（日本40 / タイ100、タイは全品タイ語対訳つき）。**人間が手で編集する唯一のファイル** |
| `build.py` | YAML を pydantic で検証して `dishes.json` を生成 |
| `dishes.json` | 生成物（静的配信するので gitignore しない） |
| `index.html` | アプリ本体。vanilla JS 単一ファイル |
| `manifest.json` / `sw.js` | PWA（ホーム画面追加・オフライン動作） |

## 起動

```bash
pip install pydantic pyyaml
```

```bash
python build.py
```

```bash
python -m http.server 8000
```

→ <http://localhost:8000> を開く。**追加操作なしでカードが1枚出れば正常。**

## スマホで使う（検証の本番環境）

夕飯を決めるのは19時のキッチンか帰り道なので、スマホから開けることが前提条件。

- Service Worker（オフライン動作）とクリップボードAPIは **https または localhost でのみ**動く。
  LAN 内の `http://192.168.x.x:8000` ではオフライン化されない（画面は動く。エクスポートは手動コピーにフォールバックする）。
- 推奨: このフォルダをそのまま **GitHub Pages** 等の https 静的ホスティングに置き、
  スマホで開いて「ホーム画面に追加」する。初回読み込み後はオフラインでも動く。

## データを編集したら

1. `dishes.yaml` を編集
2. `python build.py`（スキーマ違反・id 重複は行番号つきで落ちる。内訳サマリで分布を確認）
3. 配信し直す場合は `sw.js` の `CACHE_VERSION` を上げる（上げないと既存端末に古いキャッシュが出続ける）

抽選の重みや除外日数などの調整値は `index.html` 冒頭の `CONFIG` にまとめてある。
常備品リストの品目は同じく `PANTRY_ITEMS`。**品目名は `dishes.yaml` の ingredients と表記を一致させること**（文字列一致で「買うもの」を判定している）。

## 2週間の検証手順

1. 初日に設定（右上⚙）を開き、常備品を自分の家に合わせる。以後は基本触らない
2. 毎日、夕飯を考え始めたタイミングでこのアプリを**最初に**開く。他のレシピサイトやSNSで探し始めない
3. 提案に従う・従わないは自由。ただし操作は正直に:
   - 作る気になったら「これにする」
   - 外食・デリバリーに逃げる日は「今日は無理」
   - 決めずに閉じたら、それはそれでよい（abandoned として記録される）
4. 翌日の「昨日の〇〇、食べた？」には必ず答える（決定が実食につながったかを測る唯一の質問）
5. 2週間後、設定 → 「JSONをクリップボードにコピー」でログを回収する

### ログの読み方（1セッション = 1レコード）

| 見る指標 | 意味 |
|---|---|
| `outcome` の内訳 | decided 率が本丸。abandoned が多いなら提示が刺さっていない |
| `decided` かつ `ate_it: true` の率 | 「決まったつもり」ではなく実際に食べたか。ここが本丸 |
| `elapsed_sec` の中央値 | 決定までの時間。数分を超えるなら決定麻痺は解消していない |
| `rerolls_used` の分布 | 無制限なので「決定までに何枚流したか」がそのまま決定コストの実測値になる |
| `escalation_answer` | どの不満（時間・買い物）が多いかで Phase 1 の優先度を決める |

## 実装メモ（仕様の解釈で決めたこと）

- 「別のを見る」に**回数制限はない**（当初の3回制限は撤廃）。`rerolls_used` は計測のため数え続ける。
- カード画面上部のタブ（**タイ料理 / それ以外**）でレーンを切り替える。押すと表示中のカードも
  そのレーンから引き直す（リロールとしては数えない）。選択は保存され、初期値はタイ料理。
- **セッションは1日1回**。決定（または「今日は無理」）した日はリロードしても決定画面のまま。
  ただし「← トップ」で当日中はいつでも取り消してカードに戻れる。取り消したセッションの
  レコードはログから消え、最終的な結果だけが記録される。日付が変わると新セッション。
- エスカレーション質問（2回目のリロール直後に1度だけ）は「← トップ」で未回答のまま抜けられる。
  前日の「食べた？」も「← トップ」でスキップできる（`ate_it` は未回答 null のまま）。
- 決定後の画面は当日中ずっと開けるので、スーパーで買うものリストとして使える（チェックも保存される）。
- `ate_it: false`（決めたが食べなかった）の料理は14日除外の対象にしない。作れなかった料理は候補に戻る。
- 常備品は初回起動時に基本調味料16品だけチェック済み。タイ調味料や野菜は各自でチェックする。
- 前日フィードバックは直近の未回答の決定1件についてだけ、1日1回聞く。

## リセット（デバッグ用）

DevTools のコンソールで `localStorage.clear()` を実行してリロードすると初期状態に戻る。
